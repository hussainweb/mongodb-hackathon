## 1. Purpose and actors

FinishLine ("Track 3: Finish the Job") is a chaos-resumable GitHub and deployment release closer built for the Agents in Context Toronto hackathon (`README.md:1-5`, `docs/hackathon-options.md:1,80-85`). It accepts either an open GitHub issue or a free-form release prompt (`issue_number=0`), recalls repository-scoped rules and drift playbooks from MongoDB Atlas Vector Search, generates a structured `FixPlan`, commits a patch branch to GitHub, deploys to a target microservice, verifies real activation via an independent `GET /verify/{deployment_id}` probe rather than trusting `202 Accepted`, survives mid-run `SIGKILL` OS crashes using ACID MongoDB Atlas checkpoints, adapts mid-flight to `v1 -> v2` OpenAPI contract drift, escalates policy or low-confidence gates via ElevenLabs voice briefings and Scribe v2 speech-to-text, and supports Track 1 compensating rollbacks (`src/mongodb_hackathon/worker.py:40-127,235-718`, `src/mongodb_hackathon/app.py:585-1001`).

What actually runs today is a local two-service Python 3.14 FastAPI demonstration (`:8000` Control Room with three standalone SSR pages `/`, `/infra`, `/store` over shared `base.html` and SSE, plus `:8001` in-memory Target Deployment Service) paired with a remote MongoDB Atlas cluster, OpenAI, optional LangSmith/Logfire/ElevenLabs, and either live GitHub repositories or `dry-run/` stubs (`src/mongodb_hackathon/__init__.py:13-66`, `src/mongodb_hackathon/app.py:358-515`, `src/mongodb_hackathon/target_service.py:14,52-70`, `src/mongodb_hackathon/github_adapter.py:43-44`). Instead of the three separate microservices, Voyage AI embeddings, HTMX fragments, and `delegations`/`policies` proxy sketched in the planning brief (`docs/hackathon-options.md:14,57-71,85,107`), the implemented system uses one in-memory target service, OpenAI `text-embedding-3-small` with SHA-256 fallback, vanilla JS with `EventSource`, and `source_repo`-scoped `experience_memories` (`src/mongodb_hackathon/embeddings.py:20-46`, `src/mongodb_hackathon/mongo.py:343-408`, `src/mongodb_hackathon/static/live-run.js:187-243`).

**Human actors (roles):**

- **Operator / Demo Presenter:** Selects a repository from `demo_repos` or registers a new repo, composes a free-form prompt or selects an issue chip, picks a pacing preset (`fast`, `demo`, `slow`) or `Step-by-Step` breakpoint mode, inspects/edits/re-plans Step 1 `FixPlan` before Step 2 mutates GitHub, advances paused checkpoints, triggers `SIGKILL`/resume/rollback, injects target faults on `/infra`, and governs `experience_memories` on `/store`; exists in code via unauthenticated Control Room routes and templates (`src/mongodb_hackathon/app.py:358-1178`, `src/mongodb_hackathon/templates/index.html:19-203`, `src/mongodb_hackathon/templates/infra.html:18-262`, `src/mongodb_hackathon/templates/store.html:31-426`).
- **Developer / Evaluator:** Seeds `demo_repos` and `experience_memories` (`mise run seed`), runs Ruff/ty/pytest (`mise run check`), runs Track 3 evals (`mise run evals`), and serves the architecture walkthrough (`mise run walkthrough`); exists in code via `mise.toml`, `seed.py`, `scripts/run_evals.py`, and `tests/` (`mise.toml:1-40`, `src/mongodb_hackathon/seed.py:223-272`, `scripts/run_evals.py:176-196`).
- **Hackathon Judge / Reviewer:** Evaluates live demo behavior and LangSmith/Logfire telemetry; exists only in design documents (`docs/hackathon-options.md:10,108,120`, `docs/hackathon-resource-guide.md:15-17,27`).
- **Scoped Human Principal (`delegations` / RBAC):** Design docs propose identity-bound roles and TTL-expiring authority chains (`docs/hackathon-options.md:39,62`); does **not** exist in code—neither Control Room nor Target Service implements authentication, user principals, or a `delegations` collection (`src/mongodb_hackathon/app.py:306-318`, `src/mongodb_hackathon/target_service.py:14-20`, `src/mongodb_hackathon/mongo.py:95-113`).

## 2. External systems

- **Local `gh` CLI (`gh auth token`):** Subprocess fallback for GitHub authentication when `GITHUB_TOKEN` is unset (`src/mongodb_hackathon/github_adapter.py:16-25`).

## 5. Components per container

**Supervisor (`src/mongodb_hackathon/__init__.py`):**
- `main()` — Launches `target_service:app` (`:8001`) and `app:app` (`:8000`) as child `uvicorn` subprocesses with `--proxy-headers --forwarded-allow-ips=*` and forwards `SIGINT`/`SIGTERM` (`src/mongodb_hackathon/__init__.py:13-66`).

**Operator Control Room (`src/mongodb_hackathon/app.py` + `templates/` + `static/`):**
- Lifespan & dependency wiring (`lifespan`, `_deps`, `_resolve_active_run_id`) — Initializes `MongoStore`, schema/indexes, `GitHubSandboxAdapter`, and `httpx.AsyncClient`, and selects active runs preferring `RUNNING`, `AWAITING_APPROVAL`, or `step_paused` (`src/mongodb_hackathon/app.py:278-350`).
- Standalone SSR pages (`GET /`, `GET /infra`, `GET /store`) — Render Workspace (`index.html`), Target Infrastructure Control (`infra.html`), and MongoDB Atlas Store (`store.html`) inheriting shared `base.html` (`src/mongodb_hackathon/app.py:358-515`, `src/mongodb_hackathon/templates/base.html:1-110`).
- Repo & memory governance API (`GET/POST /api/repos`, `GET/POST /api/memories`, `POST /memories/{id}/invalidate`) — Manages `demo_repos` (with optional `create_sandbox` GitHub creation) and embeds/lists/toggles `experience_memories` (`src/mongodb_hackathon/app.py:1049-1178`).
- Run lifecycle, breakpoint & plan-edit endpoints (`POST /runs`, `POST /runs/{id}/kill`, `POST /runs/{id}/resume`, `POST /runs/{id}/advance`, `POST /runs/{id}/plan`, `POST /runs/{id}/approve`, `POST /runs/{id}/rollback`) — Creates `JobRun` docs (including `issue_number=0` and `step_mode`), manages detached worker PIDs, unpauses breakpoints (respawning crashed workers), edits or re-plans Step 1 `FixPlan` before Step 2, transcribes voice approvals, and triggers rollbacks (`src/mongodb_hackathon/app.py:585-1001`).

- Snapshot & SSE Change Streams (`GET /api/runs`, `GET /api/runs/{id}`, `GET /runs/{id}`, `GET /api/active-run`, `GET /api/active-run/stream`, `GET /runs/{id}/stream`) — Pushes `event: snapshot` frames driven by `store.watch_run_stream()` with a 2-second diff loop (`src/mongodb_hackathon/app.py:561-582,1181-1353`).

**Standalone Worker (`src/mongodb_hackathon/worker.py`):**
- CLI & job runner (`main`, `execute_job`, `_execute_job_impl`) — Parses `--run-id`/`--step-delay`, opens LangSmith `execute_finishline_job` span, records `worker_pid`, and runs 5 checkpointed steps (`src/mongodb_hackathon/worker.py:165-233,726-745`).
- Step 1 Planner & reload (`step_1_plan`) — Queries `repo_rule` + `github_fix` Vector Search scoped by `run.repo`, calls `plan_release_fix()`, checkpoints `FixPlan`, pauses if `step_by_step`, and reloads `step_1_plan` from MongoDB so operator edits apply to Steps 2–4 (`src/mongodb_hackathon/worker.py:235-290`).
- Step 2 GitHub Patcher (`step_2_github_patch`) — Uses `issue-{n}` or `task` (for `issue_number == 0`) branch slug and commits `fix_plan.patch_filename` (`src/mongodb_hackathon/worker.py:296-349`).
- Step 3 Deploy, Gate, Drift Adapter & Verifier (`step_3_deploy_and_verify`) — Checks `GET /health` upfront for `require_approval_gate`, posts `/v1/deployments`, catches `422` drift to fetch `/openapi.json` + `drift_playbook` Vector Search (`source_repo=run.repo`) + `adapt_to_schema_drift()`, optionally awaits voice/text approval, posts adapted payload, and polls `/verify/{dep_id}` up to 4 attempts (`src/mongodb_hackathon/worker.py:356-598`).

## 6. Runtime flows

### Flow 1 (Core Product Flow): Prompt/Issue to Verified Release with `source_repo` Recall, Silent-Drop Proof & `v1 -> v2` Drift Adaptation — **Implemented**
1. Operator picks a repository from `#repo-select` (`demo_repos`), edits the prompt or clicks a starter chip (`issue_number=0` or open GitHub issue), picks pacing (`fast` 0.1s / `demo` 0.5s / `slow` 2.5s / `step`), and clicks **Run Release Closer** (`POST /runs`) (`src/mongodb_hackathon/templates/index.html:19-94,682-724`, `src/mongodb_hackathon/app.py:585-646`).
2. Control Room inserts `JobRun` into `job_runs`, spawns `python -m mongodb_hackathon.worker --run-id <id>`, records `worker_pid`, and `FinishLineLiveRun` subscribes to `GET /api/active-run/stream?run_id=<id>` (`src/mongodb_hackathon/app.py:608-646,1266-1353`, `src/mongodb_hackathon/static/live-run.js:187-213`).
3. Worker Step 1 (`step_1_plan`) queries `experience_vector_idx` with `kind=["repo_rule", "github_fix"]` and `source_repo={"$in": [run.repo, "*"]}`, runs `plan_release_fix()`, and atomically writes `step_checkpoints` + `current_step=1` (`src/mongodb_hackathon/worker.py:246-281`, `src/mongodb_hackathon/mongo.py:343-388`).
4. Worker Step 2 (`step_2_github_patch`) creates `finishline/{issue-N|task}-{run_id[:6]}` and commits `fix_plan.patch_filename` via `GitHubSandboxAdapter` (`src/mongodb_hackathon/worker.py:296-347`, `src/mongodb_hackathon/github_adapter.py:172-271`).
5. Worker Step 3 (`step_3_deploy_and_verify`) checks `GET /health` for `require_approval_gate`, then posts `POST /v1/deployments` with `idempotency_key=f"{run_id}-deploy"` (`src/mongodb_hackathon/worker.py:411-440`).
6. Under `silent_drop_202`, Target Service returns `202` with `active=False`; worker's `GET /verify/{dep_id}` probe catches `active=False`, emits `probe_mismatch`, and retries with the same `idempotency_key` (`src/mongodb_hackathon/target_service.py:154-182`, `src/mongodb_hackathon/worker.py:548-588`).
7. Under `drift_v2`, Target Service returns `422 API_CONTRACT_DRIFT`; worker fetches `GET /openapi.json`, queries `kind="drift_playbook"` scoped to `[run.repo, "*"]`, runs `adapt_to_schema_drift()`, checkpoints `ADAPTED`, and posts `POST /v2/deployments` (`src/mongodb_hackathon/target_service.py:131-145,208-239`, `src/mongodb_hackathon/worker.py:441-526`).
8. After `GET /verify/{dep_id}` confirms `active=True`, worker checkpoints `VERIFIED_TOOK_EFFECT`, executes Step 4 (PR + marker comment + label on issue or PR when `issue_number=0`), and executes Step 5 (stamping `learned-{run_id}` with `source_repo=run.repo` if adapted, marking `JobRun` `COMPLETED`) (`src/mongodb_hackathon/worker.py:556-718`).

### Flow 2: Step-by-Step Breakpoint Mode & Operator Step 1 `FixPlan` Edit / Re-plan — **Implemented**
1. Operator selects `Step-by-Step` pacing (`step_mode="step_by_step"`) and launches a run (`src/mongodb_hackathon/templates/index.html:89,254-257,701`, `src/mongodb_hackathon/app.py:616`).
2. After completing Step 1 (`step_1_plan`), worker calls `_pause_if_step_by_step(store, run_id, 1)`, sets `step_paused=True, paused_after_step=1`, emits `step_paused`, and polls every `0.4s` (`src/mongodb_hackathon/worker.py:130-162,283`).
3. SSE pushes `step_paused=True` to `/` (revealing `#pause-banner` and `#plan-review-drawer`) and to the shared `#live-run-strip` on `/infra` and `/store` (`src/mongodb_hackathon/templates/index.html:531-565`, `src/mongodb_hackathon/templates/base.html:81`, `src/mongodb_hackathon/static/live-run.js:126-134`).
4. While paused after Step 1 (and before Step 2), operator either edits `FixPlan` fields (`Save Plan to Atlas`) or submits `replan_prompt` (`Re-plan Step 1`) via `POST /runs/{run_id}/plan`, which re-runs `plan_release_fix` if requested, validates `FixPlan`, atomically updates `step_1_plan`, and emits `plan_updated` (`src/mongodb_hackathon/templates/index.html:149-180,726-805`, `src/mongodb_hackathon/app.py:788-887`).
5. Operator clicks **Next Step →** (or **Advance Step ⏭** in `#live-run-strip`), calling `POST /runs/{run_id}/advance`, which sets `step_paused=False` (and respawns a fresh PID if the run had crashed) (`src/mongodb_hackathon/app.py:722-785`, `src/mongodb_hackathon/static/live-run.js:142-157`).
6. Worker exits `_pause_if_step_by_step`, refreshes `step_1_plan` from MongoDB (`cp1_refreshed`), and applies the operator's edited `patch_filename`, `patch_content`, `commit_message`, and `deployment_config` in Steps 2–4 (`src/mongodb_hackathon/worker.py:285-290,323-325,389-401,634`).

### Flow 3 (Most-Triggered Chaos Flow): Live `SIGKILL` Crash & Fresh-PID Resume — **Implemented**
1. While a worker PID is `RUNNING`, operator clicks **SIGKILL Worker** (from Workspace or shared `#live-run-strip` on `/infra` or `/store`), sending `POST /runs/{run_id}/kill` (`src/mongodb_hackathon/templates/index.html:129,812-815`, `src/mongodb_hackathon/templates/base.html:82`, `src/mongodb_hackathon/static/live-run.js:159-169`).
2. Control Room delivers `os.kill(pid, signal.SIGKILL)`, sets `status="crashed", worker_pid=None`, and emits `worker_sigkilled` (`src/mongodb_hackathon/app.py:649-686`).
3. SSE pushes `CRASHED` state to the browser, showing **Resume Fresh PID** on `/` and **Resume Crashed PID ↺** in `#live-run-strip` (`src/mongodb_hackathon/templates/index.html:522`, `src/mongodb_hackathon/static/live-run.js:126-133`).
4. Operator clicks **Resume Fresh PID** (`POST /runs/{run_id}/resume`) or **Resume Crashed PID ↺** (`POST /runs/{run_id}/advance`), spawning a new worker OS PID (`src/mongodb_hackathon/app.py:689-785`).
5. Fresh worker loads `step_checkpoints`, emits `checkpoint_skipped` for completed steps, and executes only remaining steps (`src/mongodb_hackathon/worker.py:231-244,301-309,357-366,606-614`).

### Flow 4: Approval Gate & ElevenLabs Voice/Text Escalation — **Implemented**
1. In Step 3, either `GET /health` reports `chaos_mode == "require_approval_gate"` before posting `/v1/deployments`, or `422` drift adaptation returns `needs_human_confirmation=True` or `confidence < 0.75` (`src/mongodb_hackathon/worker.py:411-430,474-489`).
2. Worker calls `synthesize_briefing()` (`eleven_flash_v2_5`) writing `src/mongodb_hackathon/static/audio/briefing-{run_id}.mp3`, updates `job_runs` to `AWAITING_APPROVAL` with `voice_audio_path`, and polls every `0.5s` (`src/mongodb_hackathon/worker.py:37,89-127`, `src/mongodb_hackathon/voice.py:15-42`).
3. Workspace displays `#approval-banner` with `<audio id="briefing-audio">` and `MediaRecorder` button (`Speak Decision`) (`src/mongodb_hackathon/templates/index.html:184-196,573-594,827-863`).
4. Operator submits text or WebM audio (`POST /runs/{run_id}/approve`); Control Room transcribes audio via `scribe_v2`, sets `halt_requested=True` on abort keywords or `approval_granted=True` otherwise, and worker resumes or rolls back (`src/mongodb_hackathon/app.py:890-958`, `src/mongodb_hackathon/voice.py:45-62`, `src/mongodb_hackathon/worker.py:112-127`).

### Flow 5: Track 1 Compensating Rollback — **Implemented (with Step 4/5 Boundary Caveat)**
1. Operator clicks **Rollback** (`POST /runs/{run_id}/rollback`) or speaks an abort word during approval (`src/mongodb_hackathon/app.py:920-931,961-1001`).
2. Control Room sets `halt_requested=True` and spawns a worker if the run is `CRASHED`, `COMPLETED`, or `AWAITING_APPROVAL` with no live PID (`src/mongodb_hackathon/app.py:969-992`).
3. Worker calls `_check_halt_or_rollback` after Steps 1, 2, or 3 (or inside approval polling), iterates checkpoints in reverse, calls `DELETE /deployments/{id}` and `github.rollback_changes()`, marks checkpoints `ROLLED_BACK`, and marks `JobRun` `ROLLED_BACK` (`src/mongodb_hackathon/worker.py:40-86,116,293,353,602`).
4. *Caveat:* Once a live worker enters Step 4 (`step_4_github_pr`), it does not check `_check_halt_or_rollback` again before finishing Step 5 (`src/mongodb_hackathon/worker.py:605-718`).

## 9. Surprises and open questions

1. **Workspace UI `step_key` mismatch hides Steps 3 and 5 checkpoint details (`src/mongodb_hackathon/templates/index.html:219-225,600` vs `src/mongodb_hackathon/worker.py:371,694`):** `VERIFICATION_STEPS` in `index.html` uses `"step_3_deploy_probe"` and `"step_5_close_issue"` (with title `"Merge PR & Close Issue"`), whereas `worker.py` persists `"step_3_deploy_and_verify"` and `"step_5_finalize"` (and neither merges the PR nor closes the issue).
